排版不是审美问题，是尊重问题。读者愿意把注意力交给你几分钟，你的句子就不该让他们反复回头。

这份清单是我写每一篇长文前都会过一遍的东西。

## 标点：中文用全角，英文用半角

最容易被搜索引擎和编辑器一起搞坏的一条。中文句子里的逗号、句号、问号、感叹号、括号、引号，全部用全角；出现在英文单词或代码旁边的，跟随那一侧的语言。

```txt
对的：我们在 2026 年发布了 v2.0 版本（历时三个月）。
错的：我们在2026年发布了v2.0版本(历时三个月).
```

引号用「」或者引号本身都可以，但一篇文章里只用一种。书名号《》只给作品名，别拿它当强调。

## 空格：中文与英文、数字之间留一个

这是唯一一条"多一个空格就变好看"的规则：

| 场景 | 写法 |
| --- | --- |
| 中文夹英文 | 用 Node.js 写脚本 |
| 中文夹数字 | 共 8 篇文章 |
| 数字带单位 | 大约 30 MB |
| 中文夹代码 | 执行 `npm run build` |
| 破折号两侧 | 不空格——像这样 |

例外是标点：中文标点两侧不加空格，因为全角标点本身自带留白。

## 段落：一句话一段也可以

中文排版最古老的美德是**首行缩进**，但在网页上，行距和段距承担了同样的功能。我倾向于：不加缩进，段间距大于行距，每段三到五句。

超过五行的段落，读者会开始跳读。这不是他们的错，是排版的错。

如果一件事有四层以上的逻辑，就拆成列表或者小标题，不要硬塞进一个长句：

- 一个段落只讲一件事
- 一个列表最多并列五条
- 一个小标题下面不超过三段

## 代码：让它"跳出来"

行内代码适合函数名、变量、命令、文件名：

```md
执行 `wrangler pages deploy dist` 之后，控制台会输出预览地址。
```

块级代码必须标注语言。一是为了高亮，二是为了让人一眼知道该用什么心态读它——是命令、是配置，还是示例：

```css
.prose code {
  font-family: var(--font-mono);
  font-size: 0.85em;
}
```

代码块里的注释用同一种语言，别中英混着来。示例尽量能直接跑，而不是"伪代码里夹一句省略号"。

## 标点之外：语气

最后一条不是规则。中文写作里最容易犯的毛病，是**把话说满**。"绝对""必然""彻底解决"——这些词在技术文章里几乎总是错的。

> 写作的诚实，体现在愿意给结论留余地：可能、在多数情况下、取决于。

留白不是含糊，是承认世界的复杂度。读者能感觉出来。
