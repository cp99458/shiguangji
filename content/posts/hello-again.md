这是我第七次给自己搭博客。前六次都死于同一个原因：我把工具当成了目的。

## 折腾简史

第一次用的是现成的博客系统，装主题、调侧边栏、加访客统计，折腾了两个周末，写了三篇文章，然后忘记密码。

后来换过五六种方案，大致是这样一条曲线：

- **WordPress**：功能最全，也最重。插件一多，什么都想改，改完就不想写了。
- **Hexo**：生成快，但 Node 依赖树庞大，两年后 `npm install` 就跑不起来了。
- **Next.js + MDX**：很优雅，直到我想升级版本，发现 API 全变了。
- **纯手写 HTML**：最自由，也最痛苦，加一篇文章要复制三个文件。

每一次迁移，我都说服自己"这次会不一样"。真正不一样的只有一件事：文章数量始终停在三到五篇。

## 这次的三条规矩

定规矩比选框架重要。这次我给自己定了三条：

1. **写作之外的东西不超过一天。** 生成器、样式、部署脚本，全部加起来一天写完，写不完就砍功能。
2. **不引入会过期的依赖。** 整个站点只有两个运行时依赖：解析 Markdown 的 `marked`，和代码高亮的 `highlight.js`。它们都可以随时替换掉，不会绑架内容。
3. **内容是第一等公民。** 所有文章都是磁盘上的 `.md` 文件，不锁在任何数据库或私有格式里。哪怕明天这个生成器坏了，文章还能被任何工具读走。

> 工具的寿命总是短于文字的寿命。所以要保证：换掉工具的那一天，文字仍然完好无损。

## 技术上它长什么样

构建脚本两百多行，做四件事：读 frontmatter、渲染 Markdown、套一个布局、写文件。没有虚拟 DOM，没有看不见的状态，`node src/build.mjs` 跑完就是一整个可以直接上传的目录。

整站是纯静态的：没有服务器，没有数据库，没有后台。搜索索引在构建时生成成一个 JSON，浏览器打开搜索框时才去取。听起来原始，但打开速度是那些"现代方案"很难追上的。

## 写作比工具重要

最有用的一个决定，是把首页上"统计、热门、评论"这些栏位全部删掉。没有阅读量，就没有表演欲；没有评论区，就不必预设读者。

剩下的是一张白纸，和一个光标。

这次我希望它活得久一点。判断标准不是代码有多漂亮，而是半年后打开编辑器时，我还想不想写。
